# EmoScope 项目结题报告初稿设计

## 目标

在 `item` 文件夹生成一份可编辑的 Word 结题报告初稿。报告严格沿用《哈尔滨工业大学大一年度项目结题报告》模板的内容逻辑，正文不少于 3000 字，并以当前代码、项目说明和可交付成果为事实依据。

## 写作策略

采用“成果展示为主、迭代叙事为骨架”的组合方式：

1. 对每一项关键成果说明最终功能、技术实现和实际价值；
2. 对与中期报告不同的内容，按“中期设想—实际问题—调整措施—最终实现”呈现；
3. 只陈述能由代码、项目文档或已有材料支持的技术事实；
4. 将产品定位为情绪记录、心理健康辅助与自我调节支持工具，不作医疗诊断或临床效果承诺。

## 文档结构

1. 封面信息和团队成员表：保留模板字段，填入已知项；教师、专家意见与签名日期保留填写位置。
2. 中文摘要、英文摘要和 3—5 个中英文关键词。
3. 项目概述：课题背景、研究内容与过程、研究方法、创新点、项目成果、项目总结六部分。
4. 结题成果说明：以功能模块、工程架构、数据与隐私、测试/交付情况组织事实性描述。
5. 参考文献：规范编号，保留并修订与情绪计算、移动端开发、心理健康辅助相关的引用。

## 内容边界与事实来源

- 当前实现的主要事实来源：项目 README、Android Java 源码、资源与构建配置、已有中期报告。
- 中期报告仅用于说明原始目标与迭代背景，不直接作为最终实现的证明。
- 对未完成、依赖第三方服务或需要后续验证的能力，明确写成限制或后续工作。

## 交付与验收

- 输出文件：`item/EmoScope项目结题报告（初稿）.docx`。
- 保留可编辑的意见、签名和日期栏。
- 正文结构、摘要、关键词、参考文献齐全；正文超过 3000 字。
- 生成后进行 Word 渲染检查，确认中文字体、表格、分页和页眉页脚无明显错位或截断。
