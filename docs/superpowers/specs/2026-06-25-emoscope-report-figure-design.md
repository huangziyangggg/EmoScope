# EmoScope 结题报告科研化重构设计

## 目标

将现有结题报告提升为可直接提交的科研风格文档：内容表述以已实现功能和可核验材料为边界，图表成为论证的一部分而非装饰，并保持现有学校结题报告格式。

## 内容策略

- 以“中期设想—工程约束—终期取舍—已实现模块—验证范围”为叙事主线。
- 保留开题与中期报告中的研究背景，但将未验证模型、性能数字和自动化判断明确标记为阶段性探索。
- 终期章节只陈述代码、界面、模块和本地数据链路能够支持的结论；不将系统定位为诊断、临床评估或替代人工支持。
- 图注、表注采用自足式写法，说明图的作用、可核验来源和结论边界。

## 图表合同

### 图 1：研发取舍与终期闭环

- 核心结论：终期系统将中期的多源探索收敛为本地优先、用户确认、可维护的产品闭环。
- 类型：流程/决策图。
- 证据：中期报告、最终工程模块和界面。

### 图 2：终期系统架构与数据流

- 核心结论：输入、端侧处理、记录回顾和支持模块以本地 SQLite 数据链路连接。
- 类型：系统架构图。
- 证据：CameraX、FaceLandmarker、SpeechRecognizer、SQLiteOpenHelper 和当前页面模块。

### 图 3：功能验证证据链

- 核心结论：结题验收以“用户任务可完成、模块有界面和代码入口、关键数据留存本地”为可复核证据链。
- 类型：证据矩阵图。
- 证据：界面截图、控制器/页面命名、功能验收描述。

### 图 4：本地优先与用户控制边界

- 核心结论：敏感内容默认留在设备端；外部 AI 解读仅由用户配置并主动发起。
- 类型：边界与决策图。
- 证据：设置页面、隐私说明和终期实现描述。

### 图 5：用户任务闭环

- 核心结论：用户可从观察或记录开始，经回顾和成长支持形成非诊断性的自我调节闭环。
- 类型：用户任务流程图。
- 证据：首页、记录页、成长页和控制中心截图。

### 图 6：中期方向与终期实现映射

- 核心结论：复杂模型和未经验证的强推断未被当作终期成果；终期保留可实现、可维护的功能模块。
- 类型：双栏映射图。
- 证据：中期方案与终期实施对照表。

### 图 7：核心界面与验收入口

- 核心结论：四个已实现页面覆盖观察记录、成长支持、历史回顾与隐私设置。
- 类型：界面板图。
- 证据：当前项目截图；只做等比例排版与标签，不更改屏幕内容。

## 视觉与导出规范

- 仅使用 Python/Matplotlib 绘制、预览、导出和质量检查图 1–6；图 7 只由 Python 进行等比例排版。
- 白色背景、深蓝结构线、低饱和蓝绿/暖灰辅助色；绿色和红色仅承载正向或风险语义。
- 中文使用可嵌入的黑体/微软雅黑替代字体，英文和数字使用 Arial/Helvetica 回退；Word 正文保持宋体与 Times New Roman。
- 每张图导出 SVG、PDF、600 dpi PNG，并在 Word 中使用 PNG 以兼容学校提交环境。
